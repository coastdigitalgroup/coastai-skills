Custom Scrollbar Styling & Accessibility

Demonstrating the difference between an inaccessible custom scrollbar (poor contrast, non-focusable) and a WCAG AA compliant custom scrollbar system with keyboard focusability and forced-colors support.

Inaccessible Pattern Before

Narrow 4px track, invisible thumb (#1a2234 on #111827 background), no tabindex for keyboard users, broken in High Contrast mode.

Container Content (Inaccessible):

1. Low-contrast scrollbar thumb makes scroll position impossible to determine visually.

2. Lack of tabindex="0" prevents keyboard navigation via Tab key.

3. Narrow 4px drag target causes pointer interaction failures for users with motor tremors.

4. Fails WCAG SC 1.4.11 (Non-text Contrast) and SC 2.1.1 (Keyboard).

5. End of scrollable area.

  • Contrast ratio < 1.2:1 (Violates WCAG SC 1.4.11)
  • Unreachable via Tab keyboard navigation
  • Touch/drag target width is only 4px
  • Scroll thumb disappears in Forced Colors Mode

Accessible Pattern After

W3C standard properties + WebKit fallbacks, 4.5:1 thumb contrast, tabindex="0", role="region", and high contrast mode overrides.

Container Content (Accessible):

1. Clear 10px scrollbar track with high-contrast thumb (#64748b on #1e293b = 3.6:1 ratio).

2. Focusable via keyboard Tab key with prominent :focus-visible outline.

3. Operable with Arrow Up/Down, PageUp/PageDown, and Home/End keys.

4. Annotated with role="region" and aria-label for screen readers.

5. Adapts to Windows Forced Colors Mode using system ButtonText and Canvas tokens.

6. End of scrollable area.

  • 3.6:1 thumb-to-track contrast ratio (WCAG AA Compliant)
  • Focusable via Tab key with visible focus ring
  • 10px drag target with hover & active feedback states
  • Fully functional under Windows Forced Colors / High Contrast
