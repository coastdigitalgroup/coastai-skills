W3C CSS Custom Highlight API vs Traditional DOM Wrapping

High-performance non-destructive text range highlighting without DOM mutations or layout thrashing.

Web application performance depends heavily on keeping the document object model clean and responsive. Traditional text search highlights forced developers to split text nodes into thousands of individual mark or span wrapper elements.

When searching long documents or log viewers, DOM node creation causes immediate layout thrashing and triggers layout recalculation across the entire subtree. Furthermore, modifying DOM text content invalidates active user text selections and causes framework reconciliation bugs in React, Vue, and Svelte.

The modern W3C CSS Custom Highlight API decouples visual styling from DOM structure. By registering JavaScript Range objects inside named CSS Highlight collections, the browser paint engine renders custom background tints and text decorations directly on the compositor thread without creating a single new DOM element.
