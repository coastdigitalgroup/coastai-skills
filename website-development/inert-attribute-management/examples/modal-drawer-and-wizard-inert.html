Naive Approach (Before)

Why Manual tabindex="-1" and aria-hidden Fails

In traditional setups, developers try to disable background content when a drawer opens by looping through interactive elements and applying tabindex="-1" and aria-hidden="true":

// NAIVE APPROACH - DO NOT USE IN PRODUCTION
function disableBackgroundNaive() {
  document.querySelectorAll('a, button, input').forEach(el => {
    el.dataset.origTab = el.getAttribute('tabindex') || '';
    el.setAttribute('tabindex', '-1');
  });
  document.getElementById('page-wrapper').setAttribute('aria-hidden', 'true');
}

Failures of this approach:

  • Does NOT stop browser text search (Ctrl+F) from finding and scrolling to off-screen elements.
  • Breaks when dynamic elements are rendered into the page while the overlay is open.
  • Does NOT block mouse click or touch events on exposed background regions.
  • Mismatches screen reader state if any descendant overrides aria-hidden.
